# External Integrations

**Analysis Date:** 2026-04-16

## Claude Code Hook System

This is the primary integration. harness-evolve registers 7 hook handlers into Claude Code's `settings.json` via `harness-evolve init`. Each hook receives JSON via stdin, processes it, and exits without blocking Claude Code.

**Registration location:** `~/.claude/settings.json` (user-scope)

**Hook event to compiled handler mapping:**

| Event | Handler file | Mode | Timeout | Purpose |
|-------|-------------|------|---------|---------|
| `SessionStart` | `dist/hooks/session-start.js` | sync | 10s | Detects and repairs missing slash commands |
| `UserPromptSubmit` | `dist/hooks/user-prompt-submit.js` | sync | 10s | Captures prompts, increments counter, injects notifications |
| `PreToolUse` | `dist/hooks/pre-tool-use.js` | async | 10s | Tracks tool usage patterns before execution |
| `PostToolUse` | `dist/hooks/post-tool-use.js` | async | 10s | Records tool outcomes |
| `PostToolUseFailure` | `dist/hooks/post-tool-use-failure.js` | async | 10s | Logs tool failures for correction pattern detection |
| `PermissionRequest` | `dist/hooks/permission-request.js` | async | 10s | Monitors permission decisions |
| `Stop` | `dist/hooks/stop.js` | async | 10s | Triggers threshold-based analysis pipeline |

**Hook input protocol:** Claude Code pipes JSON to each hook's stdin. Input is parsed and validated with Zod schemas defined in `src/schemas/hook-input.ts`.

**Notification injection:** The `UserPromptSubmit` hook writes a notification message to stdout when `config.delivery.stdoutInjection` is true and a pending notification flag exists. Claude Code displays this output as a system prompt prefix.

**Infinite loop prevention:** `src/hooks/stop.ts` checks `input.stop_hook_active` — if true (hook was triggered by a Stop hook agent), it returns immediately without re-triggering analysis.

**Settings merge strategy:** `harness-evolve init` reads `~/.claude/settings.json`, merges hook entries using `HARNESS_EVOLVE_MARKER = 'harness-evolve'` to avoid duplicating existing hooks, and writes atomically. Existing user hooks are preserved. Implementation in `src/cli/utils.ts` function `mergeHooks()`.

## Claude Code Settings.json

**Read paths (read-only scanning at analysis time):**
- `~/.claude/settings.json` — user-scope settings
- `{cwd}/.claude/settings.json` — project-scope settings
- `{cwd}/.claude/settings.local.json` — local-scope settings

All three are read in parallel by `src/analysis/environment-scanner.ts` function `scanEnvironment()` to discover installed hooks, plugins, and `allowedTools`.

**Write paths (init and auto-apply):**
- `~/.claude/settings.json` — hook registration (`src/cli/utils.ts` function `writeSettings()`), `allowedTools` expansion (`src/delivery/appliers/settings-applier.ts`)

## Claude Code Transcript Files (.jsonl)

**What it is:** Claude Code writes conversation transcripts as JSONL files (one JSON object per line).

**Discovery:** The `transcript_path` field in every hook event stdin payload points to the current session's transcript. The path is used for context association, not direct parsing by hooks.

**JSONL Reading:** `src/analysis/jsonl-reader.ts` function `readLogEntries()` uses `node:readline` with `createReadStream` to stream-parse JSONL files from harness-evolve's own log directories (`~/.harness-evolve/logs/`). Malformed lines are silently skipped.

## Claude Code Slash Commands

**Installed by `harness-evolve init`** into `~/.claude/commands/evolve/`:
- `scan.md` — `/evolve:scan` command, generated by `src/commands/evolve-scan.ts`
- `apply.md` — `/evolve:apply` command, generated by `src/commands/evolve-apply.ts`

**Version-aware updates:** Each template has a numeric `<!-- template-version: N -->` comment. `init` compares installed version vs current and overwrites stale templates only.

**Skill:** `.claude/skills/evolve/SKILL.md` is installed as `~/.claude/skills/evolve/SKILL.md`. The `/evolve` skill invokes `node dist/delivery/run-evolve.js "$PWD"` directly.

## Claude Code Environment Discovery

`src/analysis/environment-scanner.ts` function `scanEnvironment()` performs filesystem-based discovery:

**What it scans:**
- Claude Code version via `claude --version` subprocess — detects compatibility (range: 2.1.0 to 2.1.99)
- `~/.claude/plugins/installed_plugins.json` — installed plugins list
- `~/.claude/plugins/cache/{marketplace}/{name}/{version}/` — plugin capability subdirs
- `~/.claude/skills/` and `{cwd}/.claude/skills/` — installed skills
- `{cwd}/.claude/rules/` — installed rules
- `{cwd}/CLAUDE.md`, `{cwd}/.claude/CLAUDE.md`, `~/.claude/CLAUDE.md` — CLAUDE.md presence
- `{cwd}/.planning/` — GSD ecosystem detection
- `~/.claude/skills/` for `cog`-named entries — Cog ecosystem detection

## File-Based Persistence

No external database. All persistent state lives under `~/.harness-evolve/`:

```
~/.harness-evolve/
├── config.json                           # User config (src/schemas/config.ts)
├── counter.json                          # Interaction counter with session breakdown
├── recommendations.md                    # Latest rendered markdown recommendations
├── logs/
│   ├── prompts/YYYY-MM-DD.jsonl          # Captured user prompts (daily rotation)
│   ├── tools/YYYY-MM-DD.jsonl            # Tool usage events
│   ├── permissions/YYYY-MM-DD.jsonl      # Permission request events
│   └── sessions/YYYY-MM-DD.jsonl        # Session start events
├── analysis/
│   ├── pre-processed/summary.json        # Aggregated stats from logs
│   ├── environment-snapshot.json         # Environment discovery snapshot
│   ├── analysis-result.json              # Latest analysis output
│   ├── recommendation-state.json         # Applied/dismissed status per rec
│   ├── recommendations-archive/          # Rotated-out old recommendations
│   ├── auto-apply-log.jsonl             # Log of auto-apply actions
│   ├── outcome-history.jsonl            # Recommendation outcome tracking
│   ├── has-pending-notifications         # Flag file: pending notification count
│   └── backups/                         # Settings.json backups before auto-apply
└── pending/                             # Pending recommendations for interactive apply
```

**Concurrency safety:**
- `counter.json`: `proper-lockfile` (mkdir-based) + `write-file-atomic` for cross-process counter increments
- All other writes: `write-file-atomic` for crash-safe atomic replacement
- Log appends: `node:fs/promises appendFile` (atomic for small POSIX writes)

**Directory paths:** `src/storage/dirs.ts` object `paths` is the single source of truth for all storage locations.

## npm Registry

**Publish:** `harness-evolve` is published to `https://registry.npmjs.org` with provenance.
- Triggered by `v*` git tags via `.github/workflows/publish.yml`
- Users install via `npm i -g harness-evolve` or `npx harness-evolve`

## GitHub Actions

**CI:** `.github/workflows/ci.yml` — build, typecheck, test, publint, attw on push/PR to main.
**Publish:** `.github/workflows/publish.yml` — build, test, `npm publish --provenance` on `v*` tags. Requires `id-token: write` for npm provenance attestation.

No external service credentials required (no secrets, no environment variables beyond standard `HOME`).

## Authentication & Identity

**None.** No auth providers, no API keys, no external service credentials. The tool operates entirely on local filesystem data and the local Claude Code process.

## Monitoring & Observability

**Error tracking:** None. All hook errors are silently swallowed with empty `catch {}` blocks — hooks must never block Claude Code.

**Logs:** `~/.harness-evolve/analysis/auto-apply-log.jsonl` records auto-apply actions. All recommendation output goes to `~/.harness-evolve/recommendations.md`.

**Process-level:** Hook handlers always `process.exit(0)` to ensure Claude Code is never blocked by hook failures.

## Webhooks & Callbacks

**Incoming:** None.

**Outgoing:** None. No HTTP calls to external services at any point in the pipeline.
