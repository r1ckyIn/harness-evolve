    Create 4 test config fixture directories under `tests/fixtures/model-validation/` plus a README explaining their purpose:

    **Config 1: `semantic-conflict/` (MODEL-01)**
    - `CLAUDE.md`: "This project uses ES modules exclusively. All imports must use import/export syntax. TypeScript is configured with module: esnext."
    - `.claude/rules/compatibility.md`: "## Compatibility\nFor backward compatibility, configure tsconfig with module: commonjs.\nUse require() for dynamic imports in scripts."
    - Why this works: The old `conflict.ts` scanner checks 3 opposition pairs: `always/never`, `enable/disable`, `require/forbid`. "ES modules" vs "commonjs" has NONE of these keyword pairs -- only a model understands the semantic contradiction.

    **Config 2: `cross-file-inconsistency/` (MODEL-02)**
    - `CLAUDE.md`: "# Project Config\nSee rules for testing requirements."
    - `.claude/rules/testing.md`: "## Testing\nAlways run pytest before committing. Tests must pass with 100% coverage."
    - `.claude/settings.json`: `{"hooks":{"PreToolUse":[{"matcher":"Bash","hooks":[{"type":"command","command":"npm test"}]}]}}`
    - Why this works: No single old scanner correlates a rule mentioning "pytest" (Python) with a hook running "npm test" (JavaScript). The mechanization scanner would see the rule is already mechanized (hooks exist) and suppress the finding.

    **Config 3: `natural-language-hookable/` (MODEL-03)**
    - `CLAUDE.md`: "# Development Standards\n\nCode formatting must be verified automatically before any file is saved.\nEnsure the branch naming convention is enforced on every push.\nType checking should never be skipped during development."

The phrasings "must be verified automatically", "should never be skipped", and "enforced on every push" do NOT match any of these.
